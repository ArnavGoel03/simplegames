# Studio Casino 0.3.0 candidate verification

The built local studio was served on port 3122 through the existing hosted
Chromium route bridge. No production content was modified. The catalogue came
from the primary candidate `b8e046d`; final production synchronization remains
required after the primary deployment.

## Rendered checks

One page was resized sequentially through 320x720, 344x882, 690x829, 829x690,
844x390 and 1440x1000. At every size:

- Exactly five studio tiles appeared in canonical order. Casino remained fifth
  with eleven games and the existing standalone destination. Deal kept nine
  games, ending with Rummy, without another tile.
- Casino's game names fit inside its tile, its link passed a real pointer hit
  test, and the page had no horizontal overflow or failed images.
- The demonstration retained the same commitment through all six resizes.
- The footer displayed v0.3.0, the preview's source revision and its fixed UTC
  build timestamp. Phone, landscape and desktop screenshots were inspected.

An installed service-worker replacement was then simulated through the actual
registration and state-change listener. The footer displayed the existing
"A new version is ready" string at 320px and 1440px without overflow. Both
screenshots were inspected. Worker activation and reload are covered separately
by the existing and extended lifecycle tests; the browser simulation did not
replace a real production worker.

The geometry detector was calibrated by applying a 2000px game-list width and
observing document overflow or clipping before restoring the original style.
The final run had no page errors or bridge failures. Browser sessions and the
local preview server were closed afterward.
